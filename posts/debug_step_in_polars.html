Debug Step for Data Pipelines

Small function to make debugging long pipelines easier
Published

July 30, 2025

In my work I often am writing long pipelines to process polars dataframes. Sometimes, there’s a bug and I’m not sure where its happening or have an easy way to to find it.

Oftentimes, what I would do is break the pipeline and put an IPython embed() statement. Using embed is really nice because it gives you an interactive shell in the middle of your program which you can use to see what the status is of the dataframe and play around with it. You can filter to chec if certain rows or conditions exist, and look out for your edge cases. The downside has been that I would have to break something I want to test to call the embed() function. Here’s an example shown below:

import polars as pl
from IPython import embed

# First part of process I want to debug
d = (
    pl.read_parquet('raw_data.parquet')
    .group_by([])
    .agg()
    .sort(by=)
    .with_columns(
        ( pl.col() - pl.col().mean().over([])).alias('')
    )
)
embed()

# Continue the rest 
d = (
    d
    .with_columns()
    .with_columns()
)

embed()

I stumbled upon this post by Vincent Warmerdam implementing a show method for polars and inspired me to try implementing something similar using embed()

import polars as pl
from IPython import embed

def debug_step(d:pl.DataFrame, noteStr:str=None) -> pl.DataFrame:

    # makes a copy of the dataframe incase I accidently overwrite the d variable
    _d_original = d 
    if (noteStr != None):
        print(noteStr)
    
    embed()

    return _d_original

Using this I can now run my process as normal without breaking it up

# full process

This has been a nice trick where I can plug the debug_step function into my normal pipeline and run my script and do some interactive debugging in the terminal.
